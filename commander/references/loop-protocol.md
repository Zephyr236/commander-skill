## 设计意图

用户需求原文：「需要充分利用claude code的loop和goal指令，loop指令提醒指挥官
定期需要干什么需要检查干什么，需要维护什么记忆」

关键设计选择：**把"该看什么"从指挥官的推理里挪进程序**。

如果 loop 的 prompt 是"看看现在有什么要做的"，那么每轮唤醒都要重新扫描一遍
整个工作区并推理 —— 成本随会话增长而膨胀，而且容易漏项。

所以这里是：`patrol` 用代码把该看的都看一遍，输出结构化简报；
loop 的 prompt 就是「跑 patrol，按简报决策」。**每轮思考成本恒定。**

## 谁来决定开启

**指挥官决定，用户批准。**

用户不该为了让你持续工作而记住 `/loop` 的语法。正确分工是：

```
指挥官判断该开循环 → 说明节奏/动作/成本 → 用户同意 → 指挥官用 CronCreate 建立
```

### 什么时候该提议

- 任务跨度超过一次会话（等构建、等远端任务、盯指标）
- 用户说了「长期推进」「持续盯着」「别停」
- 有任务处于 `blocked`，在等外部条件
- 巡检发现有任务反复卡住，需要更密的观察

### 提议模板

```
我建议开一个巡检循环来持续推进 <任务>：

  节奏：每 20 分钟
  动作：跑 `./.commander/cmd patrol --oneline`，有 action 就按简报处理
  成本：每次唤醒约 <N> tokens；7 天后自动过期
  停止：随时说「停掉循环」，或我判断任务完成后自己停

要开吗？
```

**不拿到同意就不要建。** 自动循环等于替用户在没看着的时候持续花钱，
这和"未经允许就删文件"是同一类问题。

### 什么算同意

| 用户说了 | 是否算同意 | 你怎么做 |
|---|---|---|
| 「用指挥官推进这个任务」 | ✗ | 先提议，说明成本与节奏 |
| 「长期盯着这件事」「持续做，别停」 | ✓ | 直接建，但**建完要汇报**你建了什么 |
| 「你自己看着办」 | ✗ | 仍要提议 —— 这不是对具体花费的授权 |
| 你提议后说「可以」「开吧」 | ✓ | 建立 |

判断标准：**用户是否知道并接受了"会持续产生费用"这件事**。
不确定就先问 —— 多问一句的成本，远低于擅自跑一夜的账单。

## 两种建立方式

### ① 指挥官自建（推荐，用户零负担）

用 `CronCreate` 工具：

```
CronCreate(
  cron      = "7,27,47 * * * *",     # 每 20 分钟
  prompt    = "跑 `./.commander/cmd patrol --oneline`，"
              "有 action 就按简报处理，没有就结束本轮。详见 .claude/loop.md",
  recurring = true,
  durable   = false,                  # 会话级；跨会话靠文件状态恢复
)
```

要点：

- **cron 用非整点分钟** —— 避开 `:00`/`:30`，减少与全网其他任务撞在一起。
  每 20 分钟写 `7,27,47 * * * *` 而不是 `*/20 * * * *`
- **`prompt` 必须自包含** —— 触发时是全新轮次，不携带本次对话的上下文。
  别写「按我们刚才说的做」，要写清具体命令
- **`durable` 默认 false** —— 会话级就够；真正的持久状态在 `tasks/` 和 `memory/` 里

### ② 用户手敲（等价）

```
/loop 20m 跑 `./.commander/cmd patrol --oneline`，有 action 就按简报处理
/loop                    # 不给 prompt，读 .claude/loop.md
```

`/loop` 是 Claude Code 自带的 skill，**内部走的就是 CronCreate 这套机制**。
两种方式完全等价，区别只是谁发起。

### 停止

```
CronList()                  # 查有哪些、拿 id
CronDelete(id = "<id>")     # 停掉
```

**任务完成后主动收掉循环。** 巡检连续几轮都是 `✅ 无异常` 且任务已 `done`，
就该停 —— 别留着空转，每次唤醒都是真实花费。

用户也可以按 `Esc` 清掉自定节奏模式下待唤醒的轮次。

## patrol 的输出语义

`patrol` 的退出码：**有 action 时返回 1，没有返回 0**。
这让 loop 的 prompt 可以写得更简单。

### patrol 能发现什么

| 类别 | 触发条件 |
|---|---|
| 任务 | active 超过 1h 无更新（卡住）、blocked、建了但从没派发 |
| 结果 | outbox 有待收集、有派发失败 |
| 记忆 | 索引落后于记忆文件、记忆库为空、失败尝试已积累到阈值 |
| 契约 | 有目录契约违规记录 |
| 编制 | agent 缺 BRIEF.md |
| 后端 | 依赖未就绪 |
| 远端 | 主机不可达（需 `--remote`） |
| 预算 | 任务用量超 80% 上限 |

### 输出形式

```bash
./.commander/cmd patrol              # 完整 markdown 简报（也会落盘）
./.commander/cmd patrol --oneline    # 一行摘要，loop 用
./.commander/cmd patrol --json       # 结构化，程序用
./.commander/cmd patrol --remote     # 顺带测远端连通性
```

落盘位置：`logs/patrol-latest.md`（最新）与 `logs/patrol-history.jsonl`（历史）。

## loop.md 模板

`.claude/loop.md` 是裸 `/loop` 的默认 prompt（**上限 25,000 字节，超出截断**）。

本工作区已配好，要点是**固定的巡检动作序列**：

```markdown
跑 `./.commander/cmd patrol --oneline`。

- 输出以 ❗ 开头 → 读懂完整简报（`logs/patrol-latest.md`），按 action 项逐条处理：
  - 卡住的任务 → 读 task.md 与最近一次 outbox，判断是继续、改角度、还是标记失败
  - 待收集结果 → `outbox list --uncollected`，读回结论，`outbox collect --all`
  - 索引落后 → `memory index`
- 输出以 ⚠ 开头 → 只处理真正要紧的，其余记一笔即可
- 输出以 ✅ 开头 → 结束本轮，不要做无谓的工作

处理完如有新教训，写进 memory/attempts/。
不要在本轮开启新的长任务 —— 那是用户在主对话里该决定的事。
```

## 必须知道的硬限制

这些是**查证过的事实**，不是猜测。不了解会导致误判调度器行为。

| 限制 | 后果 | 对策 |
|---|---|---|
| **7 天自动过期** | 循环任务创建后 7 天，最后一次触发后自删 | 长任务的状态必须落在 `tasks/` 与 `memory/` 里，不能靠调度器活着 |
| **错过的触发不补** | 会话关闭期间的巡检不会补跑；忙完后只补一次 | 醒来先 `patrol` 看全貌，不要假设"上轮做过了" |
| **会话级作用域** | 新会话清空；`--resume` 恢复 `CronCreate` 任务，但**自定节奏的 `/loop` 不恢复** | 同上，靠文件 |
| 单会话最多 50 个定时任务 | — | 别给每个子任务都开 loop |
| 仅在空闲时触发 | 长派发会顺延巡检 | 派发设合理的 `--timeout`，别让一个任务挂 1 小时 |
| 固定间隔有 jitter | 循环任务最多晚 30 分钟 | 时间敏感的事别只靠 loop |
| `CLAUDE_CODE_DISABLE_CRON=1` | cron 工具与 `/loop` **整体不可用** | 排查 loop 不触发时先查它 |

### 最隐蔽的一个坑

**`disable-model-invocation: true` 的 skill 不会作为定时任务执行** ——
只会把内容当纯文本投喂给模型。

本技能的 frontmatter **绝不能加这个字段**。加了之后 `/loop 20m /commander`
看上去在跑，实际每轮只是把 SKILL.md 全文贴给模型看一遍，什么也没做。

同理，被 `skillOverrides` 或 Skill deny 规则屏蔽的 skill 也会有这个问题。

## 让状态活过 7 天

这是本方案里最需要在意的工程约束。原则：

1. **任务状态写文件**：`tasks/active/<id>/task.md` 是唯一真相
2. **教训写记忆**：`memory/attempts/` 带 `retry_when`，下一轮或下一周都能用
3. **每轮 loop 不依赖上一轮的会话上下文**：prompt 必须自包含
4. **loop 过期后要能续上**：新会话里重新 `/loop`，靠 `patrol` + 任务档案恢复现场

### 判断标准

> 如果这个会话现在被强制关闭，重启后只看文件能不能恢复全部工作状态？

不能 → 有状态还留在会话里，需要落盘。

## 排查 loop 不触发

按顺序检查：

```bash
# 1. 全局开关
echo $CLAUDE_CODE_DISABLE_CRON      # 非空则整体关闭

# 2. 定时任务列表
#    用 CronList 工具（在主对话里）查看当前会话的定时任务

# 3. 技能是否被屏蔽
#    /doctor 会报告 skill 的加载与覆盖情况
#    确认 commander 的 frontmatter 没有 disable-model-invocation

# 4. 会话是否空闲
#    loop 只在 Claude Code 运行且空闲时触发；长派发会顺延

# 5. 是否已过期
#    创建超过 7 天的循环任务已自动删除，需要重建
```

### 关于 `/goal`

`/loop` 是"按间隔重复"，`/goal` 是"朝一个条件持续推进"。
需要反复逼近某个验收标准（例如"直到压测 P99 ≤ 100ms"）时，`/goal` 更贴合。

两者可以配合：`/goal` 定义终点，`/loop` 定义巡检节奏。
