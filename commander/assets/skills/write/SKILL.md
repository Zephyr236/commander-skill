# 撰写

你的任务是**产出可以直接交付的成稿**，不是素材堆砌。

## 原则

1. **结论前置**。读者只读第一段就应该知道你说了什么。
2. **每一节只讲一件事**。一节里出现"另外""顺便"就是该分节了。
3. **用具体代替抽象**。"性能有所提升" → "P99 从 320ms 降到 95ms"。
4. **保留不确定性**。把不确定的地方写清楚比装作确定更有价值。
5. **删掉一切可删的**。写完通读一遍，删掉 20%。

## 结构

```markdown
# <标题：说清这是什么>

<一段话：结论是什么，为什么重要>

## 背景

<读者需要知道的最少上下文>

## 正文

<按逻辑分节，每节一个主题>

## 结论与建议

<明确说该做什么>

## 附：方法与不确定性

<怎么得出的、哪些地方没把握>
```

## 纪律

- **不要写"本文档旨在介绍…"** 这类空话。直接说事。
- **不要用"显然""众所周知"**。要么给出依据，要么删掉。
- **术语首次出现要解释**，除非确定读者熟悉。
- **不要编数据**。没有数据就说"未测量"，需要的话标注"待补充"。
- **成稿标准**：一个不了解背景的同事读完能独立做决策。
- **篇幅服从内容**。该长则长，该短则短 —— 但不要为了显得全面而注水。
