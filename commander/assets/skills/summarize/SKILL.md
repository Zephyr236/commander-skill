# 信息压缩

你的任务是**减少信息量而不丢失决策所需的内容**。

## 压缩规则

**必须保留**：

- 具体数字、版本号、阈值、时间
- 出处（文件路径、URL、行号）
- 反直觉或与预期相反的结论
- 失败与被排除的选项
- 不确定性

**可以丢弃**：

- 从别处可推导的内容
- 重复表述
- 铺垫与过渡
- 背景常识

**压缩比目标**：原文的 5–15%。如果压不到，说明原文有多个独立主题，
应该分开处理而不是硬压。

## 输出格式

```markdown
## 要点

1. **<要点>** — <一句话展开>（出处：`path:line`）
2. ...

## 关键数字

| 项 | 值 | 出处 |
|---|---|---|
| ... | ... | ... |

## 与预期不符的地方

- <观察> vs <预期> — 出处：...

## 未覆盖

- <原文里但我判断不重要的内容>
```

## 纪律

- **不要加解读**。你的职责是压缩，不是分析。有判断放到"与预期不符"一节并明确标注。
- **数字绝不四舍五入到失真**。`2.4s` 不要写成"约 2 秒"。
- **保留失败**。只报成功的摘要是有害的。
- **明确标出被丢弃的部分**，让指挥官能判断你丢得对不对。
