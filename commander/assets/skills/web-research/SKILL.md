# 上网调研

你的任务是**带着结论回来**，不是带着搜索结果回来。

## 核心纪律

### 1. 先想清楚要找什么

开浏览器之前，先在心里把问题写成一个**可被搜索结果回答的句子**：

```
✗ "看看 xxx 怎么样"          —— 搜索框不知道该填什么
✓ "xxx 库 2.x 版本废弃了哪个 API，替代品是什么"
```

### 2. 来源要分级

不是所有网页都一样可信。你的结论必须标出来源属于哪一级：

| 级别 | 来源 | 怎么用 |
|---|---|---|
| **一手** | 官方文档、源码、release notes、RFC | 可以直接下结论 |
| **二手** | 技术博客、Stack Overflow 高赞、教程 | 需要一手来源印证 |
| **三手** | 聚合站、AI 生成内容、无署名文章 | **不要单独作为依据** |

**官网 vs 博客冲突时，信官网。** 博客可能写于三年前，而 API 早变了。

### 3. 注意时效

每一条结论都要确认它**现在**还成立：

- 看发布日期。超过 18 个月的 API 文档，去 changelog 确认没变
- 看版本号。文档没标版本 = 很可能过时
- 找 release notes 确认最近的破坏性变更

写结论时带上时间信息：「截至 2026-09，xxx 仍然是……」

### 4. 找不到就说找不到

比编一个像样的答案更重要的，是**如实说没查到**。
如果你搜了三轮还是没有权威来源，直接写：

> 未找到权威来源。搜了 <关键词>，命中的都是 <类型>，没有官方文档。

## 输出格式

```markdown
## 结论

<直接回答问题，前置。不要铺垫>

## 依据

| 结论 | 来源 | 级别 | 日期 |
|---|---|---|---|
| xxx | [标题](url) | 官方文档 | 2026-08 |
| yyy | [标题](url) | 博客 | 2024-03 ⚠️ 可能过时 |

## 没查到的

- <什么问题没找到答案>，搜了 <关键词>，命中的是 <什么>

## 值得进一步看的

- [标题](url) —— 一句话说明为什么值得看
```

## 浏览器操作的纪律

> 这些是 browser-use 官方技能里实战打出来的，值得遵守。

### 先问：这件事需要浏览器吗？

**公开信息的一次性读取不需要浏览器。** 能用一个 HTTP 请求拿到的东西
（公开页面、API、文档），就用 fetch，别开浏览器 —— 浏览器贵得多
（每个任务几十秒 + 上万 token）。

**只有这些情况才值得开浏览器**：

| 需要 | 例子 |
|---|---|
| 交互 | 点击、填表、翻页、登录后操作 |
| 已登录的会话 | 用户的账号里才有的数据 |
| JS 渲染 | 直接 fetch 拿到的是空壳页面 |
| 反爬 | 直接请求被拦，或返回验证页 |

如果你发现 fetch 就能拿到，**直接说「这个不需要浏览器」并给出内容** ——
那比硬开浏览器更有价值。

### 操作要验证，不要假设

点完一个元素后，**读一次页面确认状态变了**。不验证的点击等于没点。
官方技能的原话是「AX node → box center → click → verify」。

- 导航后等加载完成再读内容
- 点击/输入后重新读一次，确认生效
- 页面结构和预期不符时，先重新读页面，不要照着旧结构继续做

### 登录墙：停下来问

遇到登录墙**必须停止并交回指挥官**，不要自己想办法绕过。

**唯一例外**：如果浏览器已经登录了某个 SSO，可以自动用。
但**密码、二次验证、授权同意、账号选择歧义**——一律停。

理由是：绕过登录墙可能违反服务条款，而且你不知道用户想用哪个账号。

### 提取优先用结构，不用截图

能结构化拿到的数据（DOM 查询、无障碍树）就别截图。
截图慢、费 token，而且信息有损。

只有当版式或图像本身是答案的一部分时才截图。

## 搜索技巧

- **先宽后窄**：先搜概念确认术语，再用准确术语搜细节
- **站点限定**：`site:github.com`、`site:docs.python.org` 能省很多时间
- **找一手**：搜 `xxx changelog` / `xxx release notes` 比搜 `xxx tutorial` 有用
- **查问题**：搜 `xxx <报错原文>` 比搜 `xxx 不工作` 有用
- **翻仓库**：GitHub 上直接看 `README` + `CHANGELOG` + 最近 commit 日期

## 纪律

- **不要贴搜索结果列表**。你要的是结论，不是链接堆
- **不要复述整篇文章**。摘出能回答问题的那个点
- **来源必须可点击**，用 markdown 链接
- **区分「查到」和「推断」**。推断的结论要标出来
- 页面打不开 / 需要登录 / 是付费墙 → 明确说明，换来源，不要猜内容
